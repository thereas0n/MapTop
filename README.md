MapTop — плагин на основе CounterStrikeSharp: топ убийств за текущую карту

Плагин ведёт статистику убийств за текущую карту и показывает её двумя способами. Первый — обычный center HTML, работает на любой карте. Второй — собственный HUD-слой через Steam Workshop (custom_hud_layout): плагин сам создаёт сущность и напрямую управляет ею из C# через методы SetDialogVariableStringForPlayer/SetHasClassForPlayer (появились в CounterStrikeSharp 1.0.374). VJS-скрипты не используются. Логика подсчёта для обоих вариантов - общая, отличается только вывод.

Workshop item: https://steamcommunity.com/sharedfiles/filedetails/?id=3796805765
Аддон: resource-only — только файлы панорамы (layout/style), без карты и без скриптов
Видео с работой плагина: https://drive.google.com/file/d/19RQU7LjtuQ5-ieh1WSQurI8fEuL5Xhkm/view?usp=sharing

Принцип работы:

Команда !maptop (в чате) или css_maptop (в консоли) показывает вызвавшему топ-3 по убийствам в центре экрана на 5 секунд. Можно указать число в аргументе: !maptop 2 покажет двух игроков, в пределах TopSize из конфига. В конце раунда всем игрокам автоматически показывается топ на 4 секунды. Если убийств за карту ещё не было, ничего не показывается.

Не считаются: убийства ботов, убийства ботами, тимкиллы, самоубийства, фраги во время разминки. Ушедший игрок остаётся в топе до конца карты с пометкой "(вышел)", при переподключении по SteamID результат восстанавливается. Статистика живёт ровно одну карту и сбрасывается при смене карты. mp_restartgame статистику не сбрасывает, ибо карта не меняется.

Конфиг:

Файл создаётся автоматически: addons/counterstrikesharp/configs/plugins/MapTop/MapTop.json. Параметры: CommandDisplaySeconds (время показа !maptop), RoundEndDisplaySeconds (время показа в конце раунда), TopSize (размер топа, по умолчанию 3), AutoShowAtRoundEnd (включён ли авто-показ), HudMode (center или panorama), EnableDynamicHud (создавать ли сущность HUD самому, если на карте её нет), CountBotKills (считать ли убийства ботов, только для отладки, по умолчанию false). Все значения проверяются и ограничиваются в разумных пределах, неверный HudMode автоматически откатывается до center (тот, что без худа из Workshop).

Как я проверял каждый пункт:

Установил DLL на сервер, css_plugins list показывает плагин. С другом заходили на maptop_hud, делали друг другу фраги, !maptop показывал панель с реальными никами и киллами, скрытие через 5 секунд. В конце раунда панель показывалась обоим. На de_mirage та же команда показывает center-вариант (тобиш из первой ступени).

Краевые случаи: каждый проверен отдельно: фраги в warmup не считаются, убийство бота не считается, тимкилл не считается, суицид не считается. Фильтры стоят в обработчике смерти игрока в порядке: warmup, валидность атакующего и жертвы, боты, суицид, тимкилл, и в конце проверка что SteamID nonzero.

Смена карты и выход. После changelevel топ пустой. mp_restartgame статистику сохраняет, т.к. карта не менялась — это соответствует условию "статистика живёт одну карту". Выход игрока проверен.

В конфиге менял каждый параметр и перезагружал плагин: TopSize уменьшает список, времена показа меняют длительность, AutoShowAtRoundEnd false отключает авто-показ, HudMode переключает режим вывода.

Что было непонятно и как разобрался:

Как вообще сделать свой HUD?? По заданию искал custom_hud_layout. Документации почти нет, единственный +- нормальный источник оказался внутри самого Workshop Tools: официальный пример cs_script_demo, который откопала нейронка. В нём файл point_script.d.ts с полным описанием JS API (SetHasClassForPlayer, SetDialogVariableString и остальное).

Почему HUD не появлялся?? Долго не мог получить видимые строки. Оказалось две причины: в CSS строки были скрыты через visibility: collapse по умолчанию, а dialog variables нужно ставить на ту панель, которая их читает — рабочая схема: переменные row1..row3 на родительской панели, Label ссылаются на них через {s:row1}.

Как передать данные из плагина в JS? Перебрал несколько способов и все опроверг: value у RunScriptInput - не доходит, vscript в CS2 - не существует (консоль отвечает, что команды нет), общие переменные между контекстами - не общаются. Рабочим оказался числовой протокол через имена входов.

Почему в итоге отказался от vjs совсем? Скрипт из аддона надёжно не грузится: cs_script резолвился только когда сервер крутил карту самого аддона, на стоковых картах - ошибка "Failed to load cs_script". Решение нашлось в CounterStrikeSharp 1.0.374: появились готовые методы управления custom_hud_layout прямо из C# (SetDialogVariableStringForPlayer, SetHasClassForPlayer и другие). Финальная версия плагина не содержит ни строчки JS: сущность создаётся плагином, строки топа пишутся напрямую в панель, видимость переключается классом, скрытие по таймеру тоже на стороне плагина. Из аддона осталась только панорама (layout + style), карта и скрипты из него убраны.

Как сервер подхватывает аддон? Раньше - host_workshop_map с номером item (карта аддона). В финальной версии аддон resource-only и монтируется через MultiAddonManager: сервер анонсирует аддон, клиент скачивает файлы панорамы при подключении, карта аддона не нужна. В addoninfo.txt прописан список resources (vxml/vcss), IsPlayable = false.

Видимость item. Сначала поставил "только для друзей" — друг (отсутствующий в seam) получал пустой аддон и не мог зайти. Поставил Unlisted (по ссылке): из каталога и поиска сам item скрыт, но на сервере устанавливается и работает.

ent_fire на хостинге. Локально в Hammer из инструментов воркшопа ent_fire доходил до сущности, но на выделенном локальном сервере (тоесть после билда карты) молчал. Решил тем, что плагин сам находит сущность через API и вызывает вход напрямую.

Затраченное время:

(сервер, Metamod, CounterStrikeSharp, первый плагин) — около 1.5 - 2 часов.
1 этап (статистика, фильтры, команды, конфиг, вывод) — около 6 часов. 
Осваивание Workshop Tools, Hammer, аддона, карты — около 5 часов.
Первая видимость HUD (просто его появление) — около 4-5.
Публикации, выжидания выходов обновелний аддона (этапа модерации), тесты, — около еще 6-7.
2 этап (исправная работа HUD, по той же логике, что и у первого) - жесть, но около 15 часов.
Ну и наконец финальный результат, который кажется полностью готовым и соответствующим ТЗ, исправление багов, неточностей, подводные камни, заключительные тесты - около 4 часов.
