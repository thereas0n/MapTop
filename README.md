MapTop — плагин на основе CounterStrikeSharp: топ убийств за текущую карту

Плагин ведёт статистику убийств за текущую карту и показывает её двумя способами. Первый — обычный center HTML, работает на любой карте. Второй — собственный HUD-слой, доставляемый через Steam Workshop (custom_hud_layout), работает на карте maptop_hud, задействуя имеющиеся на нем сущности с худом из моего аддона. Логика подсчёта для обоих вариантов - общая, отличается только вывод.

Workshop item: https://steamcommunity.com/sharedfiles/filedetails/?id=3796805765
Карта аддона: maptop_hud

Принцип работы:

Команда !maptop (в чате) или css_maptop (в консоли) показывает вызвавшему топ-3 по убийствам в центре экрана на 5 секунд. Можно указать число в аргументе: !maptop 2 покажет двух игроков, в пределах TopSize из конфига. В конце раунда всем игрокам автоматически показывается топ на 4 секунды. Если убийств за карту ещё не было, ничего не показывается.

Не считются: убийства ботов (с обеих сторон), тимкиллы, самоубийства, убийства во время разминки. Ушедший игрок остаётся в топе до конца карты с пометкой "(вышел)", при переподключении по SteamID результат восстанавливается. Статистика живёт ровно одну карту и сбрасывается при смене карты. mp_restartgame статистику не сбрасывает, ибо карта не меняется.

Конфиг:

Файл создаётся автоматически: addons/counterstrikesharp/configs/plugins/MapTop/MapTop.json. Параметры: CommandDisplaySeconds (время показа !maptop), RoundEndDisplaySeconds (время показа в конце раунда), TopSize (размер топа, по умолчанию 3), AutoShowAtRoundEnd (включён ли авто-показ), HudMode (center или panorama). Все значения проверяются и ограничиваются в разумных пределах, неверный HudMode автоматически откатывается до center (тот, что без худа из Workshop).

Важно упомянуть!

Панорамный HUD работает только на карте из аддона: custom_hud_layout — это сущность карты, на обычных картах её нет. Поэтому при HudMode "panorama" плагин проверяет наличие maptop_script на текущей карте: если он есть, показывает через Workshop HUD, если нет — автоматически через center. Тоесть, !maptop и авто-показ работают на любой карте, однако HUD только на той, что залита мной в Workshop.

Как я проверял каждый пункт:

Установил DLL на сервер, css_plugins list показывает плагин. С другом заходили на maptop_hud, делали друг другу фраги, !maptop показывал панель с реальными никами и киллами, скрытие через 5 секунд. В конце раунда панель показывалась обоим. На de_mirage та же команда показывает center-вариант (тобиш из первой ступени).

Краевые случаи: каждый проверен отдельно: фраги в warmup не считаются, убийство бота не считается, тимкилл не считается, суицид не считается. Фильтры стоят в обработчике смерти игрока в порядке: warmup, валидность Steam id, боты, суицид, тимкилл.

Смена карты и выход. После changelevel топ пустой. mp_restartgame статистику сохраняет, т.к. карта не менялась — это соответствует условию "статистика живёт одну карту". Выход игрока проверен на публичном хостинг сервере: в логе MAPTOP_ROW_SET_v0_r1 [Hiro (вышел) - 1], панель показала правильную строку с кириллицей и пометкой.

В конфиге менял каждый параметр и перезагружал плагин: TopSize уменьшает список, времена показа меняют длительность, AutoShowAtRoundEnd false отключает авто-показ, HudMode переключает режим вывода.

Что было непонятно и как разобрался:

Как вообще сделать свой HUD?? По заданию искал custom_hud_layout. Документации почти нет, единственный +- нормальный источник оказался внутри самого Workshop Tools: официальный пример cs_script_demo, который откопала нейронка. В нём файл point_script.d.ts с полным описанием JS API (SetHasClassForPlayer, SetDialogVariableString и остальное).

Почему HUD не появлялся?? Долго не мог получить видимые строки. Оказалось две причины: в CSS строки были скрыты через visibility: collapse по умолчанию, а dialog variables нужно ставить на ту панель, которая их читает — рабочая схема: переменные row1..row3 на родительской панели, Label ссылаются на них через {s:row1}.

Как передать данные из плагина в JS? Перебрал несколько способов и все опроверг: value у RunScriptInput не доходит, vscript в CS2 не существует (консоль отвечает, что команды нет), глобальные переменные между контекстами не общаются. Рабочим оказался числовой протокол через имена входов.

Как сервер подхватывает аддон? host_workshop_map с номером item... В addoninfo.txt должна быть прописана карта, иначе сервер грузит дефолтную; Tools при сборке перегенерирует этот файл, правку надо проверять после каждого Build'а; команда map отмонтирует воркшоп-аддон, поэтому карту из аддона можно загрузить только через host_workshop_map.

Видимость item. Сначала поставил "только для друзей" — клиент друга получал пустой аддон и не мог зайти. Поставил Unlisted: из каталога и поиска item скрыт, но по ссылке и сервером с клиентами работает.

ent_fire на хостинге. Локально в Hammer из инструментов воркшопа ent_fire доходил до сущности, но на выделенном локальном сервере (тобиш после билда карты) молчал. Решил тем, что плагин сам находит сущность через API и вызывает вход напрямую.

Затраченное время:

(сервер, Metamod, CounterStrikeSharp, первый плагин) — около 1.5 - 2 часов.
1 этап (статистика, фильтры, команды, конфиг, вывод) — около 6 часов. 
Осваивание Workshop Tools, Hammer, аддона, карты — около 5 часов.
Первая видимость HUD (просто его появление) — около 4-5.
Публикации, выжидания выходов обновелний аддона (этапа модерации), тесты, — около еще 6-7.
2 этап (исправная работа HUD, по той же логике, что и у первого) - жесть, но около 15 часов.
Ну и наконец финальный результат, который кажется полностью готовым и соответствующим ТЗ, исправление багов, неточностей, подводные камни, заключительные тесты - около 4 часов.
