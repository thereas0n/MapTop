# MapTop — плагин CounterStrikeSharp + Workshop HUD для CS2

Тестовое задание CS2RED. Плагин ведёт топ убийств за текущую карту и показывает его игрокам двумя способами:

- **Stage 1 (`HudMode: "center"`)** — стандартный center HTML через CounterStrikeSharp.
- **Stage 2 (`HudMode: "panorama"`)** — собственный HUD-слой, доставляемый через Steam Workshop (`custom_hud_layout`).

Логика подсчёта статистики общая, меняется только вывод.

- Workshop item: https://steamcommunity.com/sharedfiles/filedetails/?id=3796805765
- Карта addon'а: `maptop_hud`

---

## Stage 1 — функциональность плагина

### Команды

- `!maptop` (чат) / `css_maptop` (консоль) — показывает вызвавшему топ-3 текущей карты в центре экрана на 5 секунд. Формат: `1. Ник — N убийств` (по строке на игрока).
- `!maptop N` — показывает N игроков (ограничено `TopSize` из конфига).

### Авто-показ в конце раунда

В конце каждого раунда всем игрокам (живым и мёртвым) показывается весь топ-3 на 4 секунды. Если убийств за карту ещё не было — ничего не показывается.

### Правила подсчёта

В статистику **не попадают**:

- убийства ботов (attacker или victim — бот);
- тимкиллы (`attacker.TeamNum == victim.TeamNum`);
- самоубийства (`attacker == victim`);
- убийства во время warmup (`GameRules.WarmupPeriod`);
- события без валидного SteamID.

### Жизненный цикл

- Статистика живёт **ровно одну карту** — сбрасывается в `OnMapStart`, ничего не пишется на диск (никаких БД/файлов).
- Ушедший игрок **остаётся в топе** до конца карты с пометкой `Ник (вышел)`.
- При переподключении (по SteamID) результат восстанавливается, пометка снимается.

### Конфиг

`/game/csgo/addons/counterstrikesharp/configs/plugins/MapTop/MapTop.json` (стандартный механизм CounterStrikeSharp, генерируется автоматически):

```json
{
  "CommandDisplaySeconds": 5,
  "RoundEndDisplaySeconds": 4,
  "TopSize": 3,
  "AutoShowAtRoundEnd": true,
  "HudMode": "center"
}
```

| Параметр | Что делает |
|---|---|
| `CommandDisplaySeconds` | время показа `!maptop` (клампится 1–30) |
| `RoundEndDisplaySeconds` | время показа в конце раунда (клампится 1–30) |
| `TopSize` | размер топа и максимум для `!maptop N` (клампится 1–10) |
| `AutoShowAtRoundEnd` | включён ли авто-показ в конце раунда |
| `HudMode` | `center` (Stage 1) или `panorama` (Stage 2) |

## Stage 2 — Workshop HUD

### Архитектура

```
CounterStrikeSharp (C#)
        |  entity.AcceptInput("RunScriptInput", value: "<input>")
        v
point_script (maptop_script)  <- сущность в карте maptop_hud
        |  maps/scripts/maptop_hud.js (cs_script, серверный JS)
        v
CustomHudLayout API
  SetHasClassForPlayer(slot, "MapTopPanel", "MapTopVisible", true/false)
  SetDialogVariableString("MapTopPanel", "row1..3", "1. Ник - N")
        v
custom_hud_layout (maptop_layout) -> panorama VXML/CSS -> экран игрока
```

Всё визуальное (расположение, размеры, цвета, тексты-заготовки) лежит **внутри addon'а**:

- `panorama/layout/custom_game/maptop_hud.vxml` — разметка: заголовок + 3 строки-Label с `text="{s:row1}"` и т.д.
- `panorama/styles/custom_game/maptop_hud.vcss` — стили: панель скрыта (`visibility: collapse`), показывается классом `MapTopVisible`.
- `maps/scripts/maptop_hud.js` — серверный скрипт карты.

Плагин **не рисует HUD и не задаёт оформление** — он только передаёт данные.

### Протокол передачи данных

Экспериментально установлено: в JS через `RunScriptInput` нельзя передать произвольную строку — скриптовый вход вызывается по **имени**, а `inputData` содержит только `{ caller, activator }`. Поэтому данные передаются **числовым протоколом через имена входов**:

| Вход | Действие |
|---|---|
| `MapTopViewer_N` | выбрать слот зрителя (кому показываем HUD) |
| `MapTopClear` | очистить все строки |
| `MapTopNameReset` | начать накопление нового имени |
| `MapTopNameChar_C` | добавить символ имени (код символа, 32..1279 — латиница, кириллица, пунктуация) |
| `MapTopPlace_N` | место в топе (1..3) |
| `MapTopKillDigit_N` | добавить цифру к счётчику убийств (накопительно) |
| `MapTopRowCommit` | записать строку из накопленных данных |
| `MapTopShow` / `MapTopHide` | показать/скрыть панель для текущего зрителя |
| `MapTopTestStatic` | (отладка) статический тестовый топ |

Имена игроков передаёт **плагин** — посимвольно, кодами символов. Вместе с именем плагин передаёт и пометку `(вышел)` для отключившихся игроков: плагин точно знает имя и статус, а резолв имени на стороне JS через `GetPlayerController(slot)` ненадёжен — после выхода игрока его контроллер освобождается, и JS мог подхватить чужое имя (этот баг был найден при тестировании и исправлен именно так).

### Важное ограничение и авто-фоллбек

`custom_hud_layout` — это сущность **карты**. Панорамный HUD работает только на карте из addon'а (`maptop_hud`). На обычных картах (de_mirage и т.п.) панорамной сущности физически нет — это ограничение механики Valve, не баг плагина.

Поэтому при `HudMode: "panorama"` плагин проверяет наличие `maptop_script` на текущей карте: если сущность есть — рисует через panorama-HUD, если нет — **автоматически показывает через center-HTML** (Stage 1). Так `!maptop` и авто-показ работают на любой карте с первого запуска, а на `maptop_hud` используется полноценный Workshop HUD.

### Видимость Workshop item

Item опубликован как **Unlisted (по ссылке)**. Причина: видимость «только для друзей» технически блокирует скачивание addon'а клиентами, которые не являются друзьями автора (проверено: клиент получал пустой addon и ошибку подключения). Unlisted — «скрытый» вариант, который при этом работает: item отсутствует в поиске и каталоге Workshop, доступен только по прямой ссылке.

## Установка

1. Metamod + CounterStrikeSharp на сервере (стандартная установка).
2. `MapTop.dll` -> `/game/csgo/addons/counterstrikesharp/plugins/MapTop/`.
3. Конфиг сгенерируется при первом запуске: `/game/csgo/addons/counterstrikesharp/configs/plugins/MapTop/MapTop.json`.
4. Запуск карты из Workshop: `host_workshop_map 3796805765` (или `+host_workshop_map 3796805765` в параметрах запуска).

Проверка загрузки: `css_plugins list` -> `MapTop` в списке; в консоли при загрузке карты — `MAPTOP_HUD_SCRIPT_LOADED`.

## Что было непонятно и как разобрался

1. **Как вообще доставить свой HUD.** По ТЗ — слово `custom_hud_layout`. Нашёл официальный addon-пример `cs_script_demo` в дистрибутиве Workshop Tools, а в нём — `point_script.d.ts`, который документирует весь JS API (`CustomHudLayout.SetHasClassForPlayer`, `SetDialogVariableStringForPlayer` и т.д.). Это оказался единственный авторитетный источник: вики-страницы почти пустые.
2. **Почему статический HUD не появлялся.** Разобрался бинарным поиском по цепочке: entity -> JS -> VXML -> CSS. Оказалось две причины: (а) в CSS строки были `visibility: collapse` по умолчанию — заголовок рендерился, строки нет; (б) dialog variables читаются с панели, на которую их установили, — рабочий паттерн: переменные `row1/row2/row3` на родительской панели `MapTopPanel`, Label'ы ссылаются на них через `{s:row1}`.
3. **Как передать данные из плагина в JS.** Перебрал и опроверг несколько способов: `RunScriptInput value=...` — не доходит (в `inputData` только `caller`/`activator`); временная entity с payload в имени — activator не передаётся, `SetName` не меняет entity name; глобальные переменные — `vscript` в CS2 не существует, а контексты не общаются. Рабочий способ — числовой протокол через имена входов (см. выше).
4. **Как сервер отдаёт addon.** `host_workshop_map <publishedfileid>`. Грабли: в `addoninfo.txt` внутри addon'а должна быть прописана карта (`maps = ["maptop_hud"]`), иначе сервер грузит дефолтную карту с addon'ом «рядом», и `custom_hud_layout` не существует на карте. Отдельные грабли: Tools перегенерирует game-side `addoninfo.txt` при сборке — правку надо вносить в него и проверять после каждого Build; команда `map <карта>` **отмонтирует** воркшоп-аддон, поэтому карту из аддона можно загрузить только через `host_workshop_map`.
5. **Видимость item.** Friends-only сломал скачивание клиенту (пустой addon, ошибка подключения). Решение — Unlisted.
6. **`ent_fire` из server console.** На выделенном сервере `ent_fire` из консоли хостинга молча не доходил до сущностей (локально в Hammer та же команда работала). Решение — плагин находит сущность через API (`Utilities.FindAllEntitiesByDesignerName`) и вызывает вход напрямую (`AcceptInput("RunScriptInput", value: ...)`), минуя консоль.

**Промпт 3** (диагностика по логу сервера):

> полный лог консоли: ... MAPTOP_BRIDGE_TEST_002 ... работает тот вариант из stage 1, но худа нет. я попросил друга зайти, он зашел, но вес workshop addon'а был 0 байт. он был "только для друзей", я запустил сервер, друг не смог зайти (ошибка 15), я сделал "для всех" - он смог зайти. я так полагаю, что сервер не смог установить мой аддон? или как?

### Случай, где нейросеть ошиблась, а я это поймал

Нейросеть предложила передавать данные в JS через серверные VScript-переменные: `vscript SetScriptVar("maptop_payload", "...")` и вызов функций через `vscript MapTopSetPayload(...)`. При проверке консоль ответила **`'vscript' is not a recognized command`** — в CS2 такой консольной команды нет (это наследие Source 1 / Lua-скриптинга других игр Source 2). Кроме того, даже если бы команда существовала, cs_script (JS) и VScript — разные контексты без общих переменных. Пришлось отказаться от канала «переменные» и построить числовой протокол на именах входов `RunScriptInput`, который и заработал.

Второй случай: нейросеть несколько итераций искала причину пустых строк HUD в API dialog variables, тогда как строки просто были скрыты правилом `visibility: collapse` в CSS addon'а. Диагноз нашёлся только когда заголовок панели изменился после пересборки — это доказало, что рендерится свежий VXML, и вопрос сузился до CSS.

Третий случай: при переносе отправки данных с `ent_fire` на API-вызов `AcceptInput` нейросеть сначала вызвала `AcceptInput("MapTopTestStatic")` — то есть попыталась вызвать **несуществующий вход entity** с именем скрипт-входа. Команда вернула успех, но JS молчал. Ошибка была найдена сравнением с рабочей консольной формой: у `point_script` вход называется `RunScriptInput`, а имя скрипт-входа передаётся в параметре `value`. Правильно: `AcceptInput("RunScriptInput", value: "MapTopTestStatic")`.

## Известные ограничения

- Panorama-HUD работает только на карте `maptop_hud` из addon'а; на остальных картах плагин автоматически показывает через center-HTML.
- Топ в panorama-режиме — до 3 строк (разметка addon'а), `TopSize` больше 3 обрезается для HUD (в center-режиме — до 10).
- При остановке/перезапуске выделенного сервера Linux CS2 завершается с `Segmentation fault (core dumped)` — это известное поведение движка при shutdown, не связано с плагином (воспроизводится и без него).
- Для автозагрузки Workshop-карты при старте сервера используется `cfg/cs2server.cfg` со строкой `host_workshop_map 3796805765` (сервер стартует на дефолтной карте и сразу делает changelevel на карту из addon'а).
